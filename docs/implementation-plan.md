### Photography intake and review

Build a private, local authoring tool, not a public admin route, CMS, or production API. It must keep unpublished originals and metadata out of Git and `static`, and put only reviewed photographs into the site's content system.

**How this shipped (D-020).** The three-command intake specified here — `photos:import`, `photos:review`, `photos:promote` — was replaced by one library and one command, at Nicolas's direction:

1. Nicolas puts photographs into `.local/photography/`, which **is** the library. Placing a file there is the selection; originals are read in place and never copied or edited.
2. `.local/photography/.data/` caches derived data and previews keyed by content hash, so a rescan costs one `stat` per unchanged file.
3. `npm run photos` opens a loopback-only, token-protected studio that edits records in place and orders each photo essay's images back into that essay's own frontmatter.
4. Edits save directly to `src/content/photography/.photogrid/` as tracked source. There is no select/hold/reject state and no promotion step.
5. Publication is `git push`.

Alternative text — or an explicit decorative mark — is the single remaining requirement, because a screen reader has it instead of the image. The `captureReviewed`, `captionReviewed`, and `coordinatesReviewed` gates are gone; coordinates are an editable field rather than a gate, per Nicolas's explicit instruction, which supersedes D-007's per-image approval rule. See [photography-intake.md](photography-intake.md) for the current workflow.

Keep private intake data separate from public content data:

| Private, Git-ignored library                       | Public photograph record                                |
| -------------------------------------------------- | ------------------------------------------------------- |
| The original file, untouched, and its content hash | Stable ID and a bounded, sanitized master               |
| Extracted capture timestamp and timezone warnings  | Reviewed capture date/time and optional offset          |
| Extracted GPS and metadata-presence warnings       | Optional location label and optional coordinates        |
| Hash-keyed cache and previews under `.data/`       | Gallery inclusion, sorted newest first                  |
| Source filename and relative path                  | Optional title, caption, alt text, and photo-essay path |
